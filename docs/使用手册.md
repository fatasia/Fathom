# 渊渟 FATHOM 使用手册

## 1. 软件定位

渊渟 FATHOM 是工业企业的数据语义与智能体底座：把分散在 IT、OT、业务系统和文件中的事实，组织成可计算的对象网络、统一指标和受控工具，为问数、分析、智能体、BI、数字孪生与运营应用提供同一套可信上下文。

FATHOM 管理数据连接、对象、本体、指标、权限、质量、证据和执行；上层平台负责模型编排、工作流和应用发布。企业数据源凭证不需要交给上层平台。

## 2. 快速安装

### 2.1 环境要求

- Python 3.12 或更高版本
- Node.js 20 或更高版本
- pnpm
- Windows 10/11、主流 Linux 发行版或 macOS

FATHOM 本身不依赖容器。默认 Lite 模式使用 SQLite 保存配置和运行状态，使用 DuckDB 完成轻量分析。

### 2.2 Windows

在项目根目录执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install.ps1
.\scripts\start.ps1
```

只安装最小依赖：

```powershell
.\scripts\install.ps1 -LiteOnly
```

启动后打开 `http://127.0.0.1:8000`。

需要让本机容器或局域网上层应用访问时：

```powershell
.\scripts\start.ps1 -BindAddress 0.0.0.0 -Port 8000
```

### 2.3 Linux

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e '.[dev,connectors-sql,connectors-industrial,connectors-context]'
cd apps/web
pnpm install
pnpm build
cd ../..
.venv/bin/fathom init
.venv/bin/fathom serve --host 127.0.0.1 --port 8000
```

## 3. 第一次使用

推荐按以下顺序开始，不要一开始建设全企业大本体：

1. 选择一个边界清晰的场景，例如生产执行、质量追溯或设备运维。
2. 在“数据连接”中接入一个事实源并测试连接。
3. 在“业务知识”中点击“新建业务域”，选择数据源并提交真实业务问题。
4. 审核系统生成的对象、属性和关系候选。
5. 在“指标中心”定义最常用的 3—10 个指标。
6. 在“学习与治理”中运行认证评测，批准并发布候选。
7. 在“问与探”中用真实问题验收答案、证据和数据范围。

这样可以先形成一个可用闭环，再由查询失败、用户纠正和结构变化持续生成下一批候选。

## 4. 页面与功能

### 4.1 问与探

输入业务问题后，系统先识别对象、指标、时间和范围，再执行 Acquire、Build、Compute：

- Acquire：获取并锚定业务对象、时间和权限范围。
- Build：绑定已发布指标、关系和计算口径。
- Compute：执行确定性计算，返回数据、解释和证据。

答案页会显示当前值、对比值、影响事件、执行计划、语义版本、数据新鲜度和 trace ID。没有识别到对象或指标时，系统会要求澄清，不会猜测执行。

点击“图像理解”可上传 JPEG、PNG 或 WebP。图像会与指定业务对象上下文一起交给视觉模型，结果只进入候选证据，不自动修改生产语义。

### 4.2 业务知识

ONN 由六类元素组成：

- 对象：工厂、产线、设备、工单、物料、人员、空间等。
- 关系：包含、安装、执行、影响、流转、依赖等有效关系。
- 属性：编码、类别、状态、位置和业务特征。
- 指标：公式、粒度、单位、维度、Owner 和时间口径。
- 事件：报警、停机、检验、换型、交易和状态变化。
- 权限：角色、组织、对象范围和可执行动作。

“新建业务域”会真实发现数据结构并生成候选，不直接写入生产语义。小白用户只需选择数据源、场景并提交常问问题；专业人员仍可导入 YAML 或通过 API 管理完整契约。

### 4.3 指标中心

点击“新建指标”，填写：

- 指标名称和唯一标识
- 业务定义
- 确定性表达式
- 业务域和 Owner
- 单位、维度和别名

保存后得到待评审候选。新指标必须经过结构校验、认证问题集和人工审批后才会发布。

### 4.4 智能体网络

内置智能体按任务动态组成最短可信链路，包含数据探查、本体映射、指标构建、问题规划、探索分析、跨模态理解、受控计算、实时上下文、动作桥接、证据权限和演化治理等职责。

页面可直接运行三类受控链路：

- 可信问数：规划、语义校验、确定性计算和证据输出。
- 引导建设：发现 Schema，生成对象、属性和关系候选。
- 自适应诊断：读取指标与事件，分析影响因素，只生成动作草案。

每一步都有状态、摘要、时间和 trace；涉及生产动作时默认停在人工审批前。

### 4.5 数据连接

页面只保存非敏感配置。密码、令牌和 API Key 必须使用 `env://变量名` 引用，例如：

```text
env://FATHOM_SOURCE_PASSWORD
```

常用配置示例：

SQLite、DuckDB 或文件：

```json
{"path":"D:/data/production.csv"}
```

关系数据库：

```json
{"host":"10.0.0.20","port":5432,"database":"factory","username":"fathom_ro","schema":"public"}
```

TDengine：

```json
{"endpoint":"ws://10.0.0.30:6041","database":"manufacturing"}
```

MQTT：

```json
{
  "host":"10.0.0.40",
  "port":1883,
  "username":"fathom",
  "topics":[
    {
      "name":"plant/line01/equipment/+/telemetry",
      "schema":{"equipment_id":"VARCHAR","temperature":"DOUBLE","pressure":"DOUBLE"}
    }
  ]
}
```

OPC UA：

```json
{"endpoint":"opc.tcp://10.0.0.50:4840","username":"fathom","browse_limit":100}
```

REST：

```json
{"endpoint":"https://api.example.com/equipment","items_path":"data.items","resource_name":"equipment"}
```

图、向量、文本和 KV 数据源使用各自的 `uri`、`endpoint`、`host` 或集合配置。连接器页面会明确显示“内置”“驱动可用”或“按需”，不会把未安装驱动显示为可用。

生产查询账号应使用只读权限，并在源端限制可访问库、Schema、表和接口。

### 4.6 工程工具

轻量数据管道支持：重命名、类型转换、过滤、派生、去重、质量检查和 ONN 映射。交互预览限制为 256MB、2 线程和最多 1000 行，避免误占生产资源。全量和增量任务应经过审批后由企业调度器执行。

SQL 模板只允许单条只读 SELECT/CTE，支持命名参数、安全解析和版本时间。写操作、DDL 和多语句会被拒绝。

导入支持 CSV、JSON、JSONL、Parquet 和语义 YAML 的预检；已有语义模型 YAML 可转换为 ONN 候选。开发环境可在预检后应用完整语义契约，系统会先自动备份；生产环境禁止绕过候选、评测和审批直接导入。

导出包括语义资产包、对象 CSV、指标观测 CSV 和事件 CSV。

### 4.7 学习与治理

系统会从失败问题、重复纠正、Schema 漂移和口径差异中生成候选。候选状态依次为：

```text
待评审 → 评审中 → 已批准 → 已发布
```

也可以驳回；已发布变更可回滚。批准前必须通过四类门禁：

- 语义规划准确率
- 确定性数值执行
- 证据与 trace 完整性
- 未知问题安全阻断

页面显示的 99% 只代表已认证业务域问题集，不代表任意企业问题。新增业务域必须建立自己的真实问题集、数值基线、权限越权样本和拒答样本。

### 4.8 系统设置与模型服务

用户可配置模型 URL、API Key、模型 ID、协议模式和基础参数。系统能自动获取模型列表，并探测 Responses、Chat、Messages、Embedding 和视觉能力。模型目录可读取但生成失败时，会明确显示“仅模型目录”，不会误报可用。

模型按角色路由：规划、语义抽取、解释、视觉、嵌入和上层 Agent 可以使用不同模型。模型只负责理解、候选和解释；权限、指标计算、对象范围和证据由 FATHOM 确定性执行。

页面输入的模型密钥写入操作系统凭证库且不回显；服务器建议使用 `env://变量名`。

## 5. 真实数据写入

除了直接查询外部数据源，ETL、流处理和边缘程序也可以通过以下接口写入轻量服务层：

```text
POST /api/v1/ingestion/objects
POST /api/v1/ingestion/relations
POST /api/v1/ingestion/metric-observations
POST /api/v1/ingestion/events
```

单批最多 10000 条。指标观测写入前会校验指标是否已发布、对象是否存在；相同指标、对象和观测时间会更新而不是重复插入。

## 6. 权限与审计

Lite 本机模式默认关闭认证。生产环境应复制 `config/fathom.production.example.yaml`，开启 `auth_enabled`，并配置角色和对象范围。

生成令牌摘要：

```powershell
.\.venv\Scripts\fathom.exe token-hash "一段足够长的随机令牌"
```

配置文件只保存 SHA-256 摘要，不保存原始令牌。调用时使用：

```http
Authorization: Bearer <token>
```

内置角色：

- viewer：问数、语义检索和只读对象上下文。
- operator：在 viewer 基础上执行管道、数据写入、智能体和跨模态任务。
- semantic_owner：管理数据源、模型、语义、治理和备份。
- admin：系统管理和审计读取。

`object_scope` 限制可直接查询的对象；查询、A2A、MCP 和内置智能体共用同一范围。所有非 GET 调用记录 principal、角色、路径、状态、耗时和客户端地址，不记录请求正文和密钥。

## 7. 备份、恢复与迁移

SQLite 模式下，“立即备份”会生成一致性 ZIP，包含数据库快照、语义文件和 manifest。恢复前必须二次确认，系统会先创建保护性备份。

默认目录：

```text
data/fathom.db
data/backups/
semantic/
```

标准模式使用 PostgreSQL 时，数据库备份应使用企业现有备份体系；语义资产仍可从页面单独导出。迁移前先停写、完成备份、校验语义包，再切换 `database_url`。

## 8. 接入 Dify

### 8.1 启动本地 Dify

本机已经准备好脚本：

```powershell
.\scripts\dify-local.ps1 -Action up
.\scripts\dify-local.ps1 -Action status
```

打开 `http://127.0.0.1/install` 完成首次管理员初始化。停止服务：

```powershell
.\scripts\dify-local.ps1 -Action down
```

### 8.2 导入 FATHOM 工具

1. 让 FATHOM 监听 `0.0.0.0:8000`。
2. 在 Dify 的自定义工具页面导入 `integrations/dify/fathom-openapi.yaml`。
3. Dify 运行在容器中时，Server URL 使用 `http://host.docker.internal:8000/api/v1`。
4. 如果 FATHOM 开启认证，为工具配置 Bearer Token；不要把 Token 作为普通工作流变量传递。
5. 在工作流或 Agent 中调用 `search_semantics` 或 `ask_data`。
6. 把返回的 `trace_id` 保留在应用日志中，便于跨系统定位。

独立契约测试：

```powershell
.\.venv\Scripts\python.exe scripts\dify-contract-smoke.py
```

Dify 只调用 FATHOM 的受控工具，不需要保存数据库、TDengine、MQTT 或其他事实源凭证。

## 9. 接入其他上层平台

FATHOM 提供三种通用入口：

- OpenAPI：`/openapi.json` 和 `/api/v1/*`
- MCP：`POST /mcp`
- A2A：`/.well-known/agent-card.json` 与 `POST /a2a`

上层平台只需支持其中一种协议。问数返回统一的 `answer`、`plan`、`data`、`evidence`、`quality_warnings`、`trace_id`、`semantic_version` 和 `data_freshness`。数字孪生和运营应用可调用对象上下文接口：

```text
GET /api/v1/ontology/instances/{object_id}/context
```

## 10. 生产部署

1. 将 `config/fathom.production.example.yaml` 复制为独立生产配置。
2. 生成管理员和服务账号令牌摘要，设置最小角色和对象范围。
3. 数据源和模型密钥通过环境变量或企业密钥系统注入。
4. FATHOM 监听内网地址，由反向代理提供 TLS、域名、限流和访问日志。
5. 单实例或中小规模场景使用 SQLite；多实例、高并发写入和高可用场景使用 PostgreSQL。
6. 外部大数据计算留在现有引擎，FATHOM 保存语义、计划、证据和治理状态。
7. 上线前运行完整测试、认证问题集、备份恢复演练和权限越权测试。

配置优先级为：环境变量、YAML、Web 持久化、默认值。生产配置应进入版本管理，但密钥明文不能进入仓库。

## 11. 常见问题

### 页面能打开，但数据源连接失败

先检查驱动状态、网络、端口、只读账号和 `env://` 环境变量。容器中的地址与宿主机 `127.0.0.1` 不是同一个网络空间。

### 能获取模型列表，但不能生成

这通常表示 URL 和令牌可读取模型目录，但生成权限、额度或协议不匹配。查看探测结果中的协议和错误摘要。

### 问数要求澄清

对象或指标没有被唯一识别。先确认对象实例、指标别名、scope 和语义版本；不要用提高模型随机性掩盖语义缺失。

### Dify 无法访问 FATHOM

确认 FATHOM 监听 `0.0.0.0`，Dify 的 Server URL 使用 `host.docker.internal`，Windows 防火墙允许本机 Docker 网络访问 8000 端口。

### SQLite 是否可以长期使用

可以用于单机、边缘、小团队和中小规模元数据/观测服务。多实例并发写、高可用、复杂权限和集中备份场景应切换 PostgreSQL。SQLite 是默认轻量方案，不是所有规模下的平替。
