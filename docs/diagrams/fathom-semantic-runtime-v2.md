# FATHOM 语义运行时架构图说明

## 交付物

- 可编辑源文件：`fathom-semantic-runtime-v2.mmd`
- 文档嵌入版本：`fathom-semantic-runtime-v2.svg`
- 评审与预览版本：`fathom-semantic-runtime-v2.png`

## 设计假设

- FATHOM 保留现有问数、MCP、Agent 与治理入口，不引入第二套语义资产目录。
- PostgreSQL、SQLite 等数据源只通过连接器执行只读物理计划；密码使用环境变量引用，不进入资产库或执行收据。
- AI 只参与需求探索、候选映射和洞察建议，发布、鉴权、执行、质量校验与副作用动作保持确定性。
- 映射版本、策略决策、数据质量、血缘和执行收据共同构成可审计证据链。
- 多源路由先按来源状态与优先级选择，失败后记录尝试并切换至下一条已发布映射。

- [x] 体验层、网关层、语义运行时、控制面、数据面与受控智能分层清晰。
- [x] 从自然语言/MQL 到真实数据源执行的主链路完整。
- [x] 映射版本化、兼容性校验、发布与回滚职责已标出。
- [x] PEP 集中鉴权位于执行前，覆盖查询和能力调用。
- [x] 数据质量、开放血缘和不可变执行收据位于执行证据链上。
- [x] MCP/Agent 只暴露已发布、最小权限能力；副作用动作需审批且支持幂等。
- [x] 需求证据、黄金问题评测和运行反馈构成持续演进闭环。
- [x] SVG/PNG 已从同一 Mermaid 源渲染并完成桌面可读性复核。

## 重新渲染

在仓库根目录设置本机 Chrome 路径后，使用 diagram-generator 的 Mermaid 渲染器生成 SVG 与 PNG；两种输出必须来自同一 `.mmd` 文件，避免图文漂移。
