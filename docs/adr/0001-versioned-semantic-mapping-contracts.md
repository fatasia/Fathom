# ADR-0001：用版本化映射契约连接语义资产与物理数据

## Status

Accepted — 2026-08-25

## Context

FATHOM 已有语义资产、数据源发现和 MQL，但外部数据源只完成连接测试与 Schema 发现。语义指标尚不能通过稳定、可评审、可回滚的契约解析到物理表、列、时间字段和维度字段。

## Decision

引入独立的 `MappingContract`：每个版本只绑定一个语义指标与一个数据源，声明表/资源、对象列、数值表达式、时间列、维度列、聚合方式和质量约束。映射使用 draft/published/retired 生命周期；同一指标可有多个已发布来源，由路由器按优先级、健康状态和新鲜度选择。

映射只描述允许的选择器，不保存任意 SQL。物理计划由受控编译器生成，标识符必须来自已发现/声明的映射，值只能以绑定参数进入查询。

## Consequences

### Positive

- 语义、物理数据和责任人之间可追踪；
- 映射可评审、版本化、回滚并进行模式漂移检测；
- 多数据源路由不污染语义内核；
- LLM 无法提交任意 SQL。

### Negative

- 每个指标/来源需要维护映射；
- 复杂派生指标暂时只能使用有限聚合与受控表达式；
- Schema 演化会产生显式治理工作。

## Alternatives Considered

- 在语义 YAML 中直接写 SQL：耦合数据源且难以安全审查。
- 让模型即时生成 SQL：不可复现，越权和成本风险高。
- 先同步所有数据到内部观测表：简化执行，但失去实时性和源端权限边界。
