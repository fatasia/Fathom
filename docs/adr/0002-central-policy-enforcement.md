# ADR-0002：查询、能力和动作统一经过策略执行点

## Status

Accepted — 2026-08-25

## Context

HTTP 中间件已经提供角色和对象范围控制，但内部查询、连接器、MCP 工具与未来动作如果各自判断权限，会产生绕过路径。外部执行还需要只读、行数、超时、来源和副作用约束。

## Decision

建立应用层 `PolicyEnforcementPoint`。每次运行产生 `PolicyDecision`，至少包含主体、角色、动作、资源、对象范围、允许/拒绝、义务和原因。

- 查询动作必须只读，并将对象范围下推为绑定谓词；
- 能力调用继承能力定义的最小角色与副作用等级；
- 有副作用动作默认 `approval_required`，没有批准令牌不得执行；
- HTTP 鉴权仍负责入口身份，PEP 负责领域级运行授权，两者不可互相替代。

## Consequences

### Positive

- 所有执行路径有一致权限语义和审计记录；
- MCP/Agent 无法绕开查询和连接器限制；
- 后续可替换为 OPA 等外部 PDP，而不修改业务调用方。

### Negative

- 内部调用也必须显式携带执行上下文；
- 开发环境关闭认证时仍要生成 local/admin 策略决定。

## Alternatives Considered

- 只依赖 FastAPI 中间件：无法控制内部工具调用和数据下推。
- 把权限写入本体规则：混淆知识推理与强制授权。
- 每个连接器自行判断：策略漂移且难以审计。
