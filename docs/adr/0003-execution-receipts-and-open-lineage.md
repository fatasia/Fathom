# ADR-0003：所有外部执行生成不可变执行收据

## Status

Accepted — 2026-08-25

## Context

可信答案不仅需要语义定义，还需证明某次运行使用了哪个映射、计划、策略、来源和数据时间。仅保存自然语言答案或 SQL 文本不足以回放、定位漂移或做影响分析。

## Decision

每次外部查询、能力调用和动作尝试都写入 `ExecutionReceipt`。收据记录逻辑计划哈希、物理计划（脱敏）、映射/策略/能力版本、主体、状态、耗时、行数、结果哈希、新鲜度、质量结果、错误和父级 trace。

同时写入运行依赖边，核心概念对齐 OpenLineage 的 Run/Job/Dataset，但内部保留 FATHOM 的语义资产和策略维度。收据追加写，不原地篡改；敏感配置和凭证永不进入收据。

## Consequences

### Positive

- 查询可回放、对账、审计和影响分析；
- 模式漂移、质量失败和策略拒绝都有统一证据；
- 可建立发布前后黄金问题比较。

### Negative

- 增加存储和脱敏责任；
- 对高吞吐场景需要后续归档与采样策略。

## Alternatives Considered

- 只写应用日志：难以稳定查询和关联版本。
- 保存完整结果集：泄露与存储风险过高。
- 只存 SQL：无法证明策略、映射、质量和数据源状态。
