# 渊渟 FATHOM 部署与接入指南

本文覆盖三件事：部署 FATHOM、配置大模型、把可信问数与知识检索能力接入 Dify。

## 1. 部署结构

FATHOM 默认采用 Lite 架构：

- 一个 Python Web 服务，默认端口 `8000`
- 一个 SQLite 文件，保存语义、配置、运行记录和内置知识库
- DuckDB 负责本地文件和分析型计算
- Vue 页面已编译到 Python 服务中
- 企业事实数据默认留在原系统，通过只读连接器访问

部署包不包含运行数据库、密钥、缓存、测试截图和 Dify 运行卷。

## 2. Windows 部署

### 2.1 环境

- Python 3.12 或更高版本
- Node.js 20 或更高版本
- pnpm

解压部署包后，在项目根目录执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
Copy-Item config\fathom.example.yaml config\fathom.yaml
.\scripts\install.ps1 -LiteOnly
.\scripts\start.ps1 -BindAddress 0.0.0.0 -Port 8000
```

浏览器打开：

```text
http://服务器地址:8000
```

需要 PostgreSQL、MySQL、TDengine、MQTT、OPC UA、Neo4j、Qdrant 等连接器时，安装完整依赖：

```powershell
.\scripts\install.ps1
```

### 2.2 仅运行已编译页面

部署 ZIP 已包含编译后的 Web 页面。目标服务器只运行现有页面时，可以只安装 Python：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m fathom.cli init
.\scripts\start.ps1 -BindAddress 0.0.0.0 -Port 8000
```

修改 Vue 源码后，才需要进入 `apps/web` 执行 `pnpm install` 和 `pnpm build`。

## 3. Linux 部署

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e .
cp config/fathom.example.yaml config/fathom.yaml
.venv/bin/fathom init
FATHOM_CONFIG_FILE="$PWD/config/fathom.yaml" \
  .venv/bin/uvicorn fathom.main:app --host 0.0.0.0 --port 8000
```

建议由 systemd 托管。将路径和运行用户替换为实际值：

```ini
[Unit]
Description=FATHOM Industrial Semantic Core
After=network.target

[Service]
Type=simple
User=fathom
WorkingDirectory=/opt/fathom
Environment=FATHOM_CONFIG_FILE=/opt/fathom/config/fathom.yaml
EnvironmentFile=-/opt/fathom/config/fathom.env
ExecStart=/opt/fathom/.venv/bin/uvicorn fathom.main:app --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启动并验证：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now fathom
curl http://127.0.0.1:8000/api/v1/health
```

## 4. 配置大模型

FATHOM 支持 OpenAI 兼容接口、Responses、Chat Completions、Messages 和 Embeddings。模型负责意图理解、语义抽取、解释和跨模态理解；指标值仍由确定性查询计算。

### 4.1 页面配置

1. 打开“系统设置”。
2. 在“模型服务”中点击新增。
3. 选择服务类型；不确定时选择“OpenAI 兼容服务”。
4. 填写 Base URL，例如 `https://model.example.com/v1`。
5. API 模式选择“自动”，系统会探测可用协议和模型列表。
6. 选择自动发现的模型，也可以手动输入模型名。
7. 填写 API Key。页面会写入操作系统凭证库，不把明文保存到数据库或 YAML。
8. 设置基础参数并保存，然后点击“探测”。
9. 在“模型路由”中分别绑定规划、语义抽取、解释、视觉、嵌入和 Agent 角色。

推荐初始参数：

| 角色 | temperature | 说明 |
| --- | ---: | --- |
| 规划与意图 | 0 | 保持计划稳定 |
| 语义抽取 | 0 | 减少术语漂移 |
| 答案解释 | 0.2 | 允许有限表达变化 |
| 视觉理解 | 0.1 | 优先忠于画面事实 |
| 上层 Agent | 0.2 | 兼顾稳定和任务分解 |

### 4.2 配置文件与环境变量

生产服务器推荐使用环境变量保存密钥，在 `config/fathom.yaml` 中只保存引用：

```yaml
model_gateway:
  providers:
    - key: primary_reasoner
      name: 主推理模型
      provider_type: openai_compatible
      base_url: https://model.example.com/v1
      api_mode: auto
      default_model: model-name
      secret_reference: env://FATHOM_PRIMARY_MODEL_API_KEY
      enabled: true
      parameters:
        temperature: 0.1
        top_p: 0.9
        max_output_tokens: 4096
        timeout_seconds: 60
  routes:
    planner: primary_reasoner
    semantic_extractor: primary_reasoner
    explainer: primary_reasoner
    agent: primary_reasoner
```

Windows 当前会话：

```powershell
$env:FATHOM_PRIMARY_MODEL_API_KEY = '在此设置密钥'
.\scripts\start.ps1 -BindAddress 0.0.0.0
```

Linux 的 `config/fathom.env`：

```text
FATHOM_PRIMARY_MODEL_API_KEY=在此设置密钥
```

配置优先级为：环境变量、YAML、页面持久化、系统默认值。模型探测成功不等于问数准确率达标；发布语义和模型路由前仍应运行企业自己的认证问题集。

## 5. 接入 Dify

### 5.1 前提

- FATHOM 已使用 `0.0.0.0:8000` 启动
- Dify 已单独安装并能登录
- Dify 容器可以访问宿主机的 `host.docker.internal:8000`

先从 Dify 容器验证：

```powershell
docker exec docker-api-1 python -c "import urllib.request; print(urllib.request.urlopen('http://host.docker.internal:8000/api/v1/health').read().decode())"
```

### 5.2 推荐方式：OpenAPI 工具 + Chatflow

这是日常对话问数的首选组合：FATHOM 负责对象、语义、指标、权限、计算和证据，Chatflow 负责多轮对话、通用知识回答与自然语言表达。

先注册工具：

1. 进入 Dify 的“工具 → 自定义工具”。
2. 点击“创建自定义工具”。
3. 名称填写“FATHOM 工业问数”。
4. 点击“从 URL 导入”。
5. 输入：

   ```text
   http://host.docker.internal:8000/api/v1/integrations/dify/openapi.yaml
   ```

6. 开发环境鉴权选择“无”，保存。

也可以下载并粘贴完整 YAML：

```text
http://FATHOM服务器:8000/api/v1/integrations/dify/openapi.yaml
```

保存后可看到以下工具：

- `ask_data`：返回可直接回复用户的自然语言文本，用户只需提供 `question`
- `ask_data_structured`：返回计划、证据、质量状态和追踪信息
- `search_enterprise_knowledge`：检索内置和外接知识库
- `search_semantics`：搜索对象、指标和业务定义
- `get_object_context`：获取对象与一跳关系
- `run_controlled_agent_flow`：执行受控智能体链路

再导入对话应用：

1. 在 Dify 工作室选择“导入 DSL 文件”。
2. 选择 `integrations/dify/fathom-chatflow.yml`。
3. 确认工具节点指向“FATHOM 工业问数 / ask_data”。
4. 在 LLM 节点选择工作区中可用的对话模型。
5. 发布后即可连续对话，不需要填写工厂、产线或对象 ID。

企业事实尚未接入时，Chatflow 会明确说明没有可验证的企业数据；定义、分析方法、使用帮助和一般对话仍能正常回答，不会用示例数字冒充真实结果。

### 5.3 其他接入方式

#### 粘贴或上传 OpenAPI

不能从 URL 访问时，打开以下地址下载 YAML，再粘贴或上传到 Dify 自定义工具页面：

```text
http://FATHOM服务器:8000/api/v1/integrations/dify/openapi.yaml
```

仓库内对应文件为 `integrations/dify/fathom-openapi.yaml`。

#### 自建 Chatflow

新建 Chatflow，连接以下节点：

```text
用户输入
  → FATHOM / ask_data，question = sys.query
  → LLM：结合用户问题与 ask_data.text 组织回答
  → 直接回复
```

LLM 提示词必须约束：企业数值只能采用 FATHOM 已验证结果；FATHOM 无数据时不得补造；定义、方法和通用问题可以正常回答。

#### Workflow

Workflow 适合定时任务、批处理和被其他系统调用，不提供聊天式界面：

```text
用户输入 query
  → FATHOM / ask_data，question = query
  → 输出 ask_data.text
```

需要计划、证据或 trace 时改用 `ask_data_structured`。

#### Agent

Agent 适合模型自主选择多个工具并进行多步任务。启用 `ask_data`、`search_semantics`、`search_enterprise_knowledge` 和 `get_object_context`，并在指令中明确：企业数值必须调用 FATHOM，不能自行生成。

#### HTTP 节点或代码调用

不注册自定义工具时，可以在任意支持 HTTP 的编排平台调用：

```http
POST http://FATHOM服务器:8000/api/v1/query/answer
Content-Type: application/json

{"question":"昨天的 OEE 是多少？"}
```

返回 `text/plain`，可直接作为对话回复。需要完整结构时调用 `/api/v1/query/ask`。其他智能体软件还可以按需使用 FATHOM 的 OpenAPI、MCP 或 A2A 能力入口。

### 5.4 本机已接入的应用

本机 Dify 已创建并发布“FATHOM 问数助手”Chatflow。打开 Dify 工作室即可找到；它使用“用户输入 → FATHOM 问数 → LLM → 直接回复”的对话链路。原来的 Workflow 只适合单次运行，因此不会显示连续对话框。

部署到另一台机器时，仍需按 5.2 节导入工具与 Chatflow，因为 Dify 的工具和应用按工作区保存。

## 6. 数据、备份和升级

- 默认数据库：`data/fathom.db`
- 备份目录：`data/backups`
- 语义契约：`semantic/`
- 主配置：`config/fathom.yaml`
- 密钥：环境变量或操作系统凭证库，不进入 ZIP 和数据库备份

升级前先在“工程工具 → 迁移与恢复”创建一致性备份。部署新版本后保留 `data/`、生产配置和环境变量，再启动服务；数据库表会在启动时补齐。

## 7. 验收

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
.\.venv\Scripts\python.exe scripts\dify-contract-smoke.py --base-url http://127.0.0.1:8000
```

页面验收：

1. 数据接入能够保存并测试真实数据源。
2. 问数在空库时返回“暂无真实数据”，不出现演示数值。
3. 模型服务能够发现模型并通过探测。
4. 内置知识库导入后能返回原文和来源。
5. Dify Chatflow 无需额外输入即可连续对话；企业问数调用 FATHOM，通用问题由模型自然回答。

## 8. 安全声明

FATHOM 的数据库连接应使用专用只读账号、最小权限、TLS 和网络白名单。凭证只通过环境变量或操作系统凭证库引用，不应写入 YAML、代码、工作流变量、日志、导出文件或部署 ZIP。FATHOM 不会把企业数据源密码交给上层对话平台。

大模型的 Base URL、模型名和 API Key 属于企业敏感配置。API Key 只保存为密钥引用，不进入数据库备份和发布包；生产环境应使用企业批准的模型端点、加密传输，并按数据分级控制可发送的业务上下文、日志留存和供应方数据保留策略。模型只负责理解与表达，企业指标值由受权限和语义约束的确定性计划计算。

备份与语义导出默认不包含密钥，但可能包含业务对象、指标口径、数据结构和知识文档，同样应按照企业数据资产要求加密、授权和留存。
